The problem

Finance, operations and market-research teams still copy prices, totals and line items by hand from PDFs, scans and phone photos. It's slow, error-prone, and it doesn't scale. Generic OCR gives you text, not the fields you need, and it can't tell Coke Zero 33cl from Coke Original 35cl.

Any file

Digital PDFs, scanned PDFs, JPG/PNG photos, Excel, CSV and Word, uploaded in bulk.

Your fields

You define the template: names, types, required flags, tables. No code, no model training.

Trustworthy output

Every value is checked against the page and the maths, then scored. Uncertain values go to a person.

How it works

Every file runs through one background pipeline. Confidence decides whether a value is exported directly or checked by a person first.

Upload→Read text or image→LLM extraction→Validate→Confidence→Review if unsure→Export
01 · Define

Template → schema

Your template becomes a Pydantic model at runtime. The model must return exactly those fields and types.

02 · Read

Text first, vision when needed

Digital files send text (cheap, exact). Scans and photos send the image to Gemini, which sees the layout.

03 · Check

Validate and score

Is the value printed on the page? Do line items add up to the total? Are required fields present?

04 · Recover

Retry, fall back, never crash

Bad output is re-prompted with the error, then sent to a second model. Failures are recorded, not lost.

Every price tied to one exact product

One brand can have 20+ SKUs at different prices. SenseDoc extracts brand, flavour, size, pack type and pack count separately, filters the catalogue by the hard attributes, and ranks the rest by flavour. If more than one SKU still fits, it asks. It never guesses, and it learns from each correction.
